# Transaction Intelligence Platform

Production-grade ML platform for a multi-tenant SaaS that processes business transaction data at scale. Demonstrates the full ML lifecycle on a synthetic dataset modeled on a real B2B payments / commerce SaaS.

## Data

Synthetic multi-tenant transaction dataset generated by `scripts/generate_data.py`. All synthetic — no real PII. Approximate scale on default seed:

- 500 merchants (tenants) across 12 industry verticals
- 50,000 customers with realistic lifetime curves
- 5,000,000 transactions over 24 months
- 2,000 SKUs with categories, prices, and free-text descriptions
- ~120,000 support tickets as free text (powers vector search + LLM agent)
- Injected anomalies (~0.8%) and churn labels derived from behavioral decay

Realistic patterns built in: weekly + yearly seasonality, customer cohort decay, merchant-level pricing distributions, basket affinity, and a "declining engagement → churn" signal you can actually learn.

## Architecture

```
        │                  │              │           │
        └──────────┬───────┴──────────────┘           │

                                  │

                  (Postgres offline + Redis online)
                                  │

```

## ML systems

| System | Type | Models |
|---|---|---|
| Churn prediction | Binary classification | LogReg baseline, GradientBoosting |
| Transaction anomaly | Unsupervised + supervised | IsolationForest, GBM head |
| Product recommendation | Implicit MF + ranker | ALS-style, LightGBM ranker |
| Semantic ticket search | Retrieval | Sentence embeddings + pgvector |
| Business intelligence agent | LLM tool-use | Claude with SQL + vector tools |

## Engineering

- **Feature store**: thin Postgres offline store with point-in-time joins, Redis online cache for low-latency serving
- **Training**: sklearn pipelines + LightGBM, joblib-serialized, registered with metrics, training window, feature schema; champion/challenger compare
- **Serving**: FastAPI loads models at startup; every prediction logged for monitoring
- **Monitoring**: nightly job computes PSI on features and KS on outputs against the training reference distribution
- **CI/CD**: GitHub Actions runs unit tests + a smoke-train on a tiny sample on every PR
- **Containerized**: Docker Compose brings up Postgres+pgvector, Redis, API, worker

## Quick start

```bash
docker compose up -d postgres redis
python -m scripts.generate_data --merchants 500 --customers 50000 --transactions 5000000
python -m scripts.load_to_postgres
python -m scripts.train_all
uvicorn app.api.main:app --reload
```
